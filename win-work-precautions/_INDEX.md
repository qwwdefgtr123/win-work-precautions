# win-work-precautions — Windows 环境 AI Agent 全局注意事项文档集

> 本文档集从大量本机实操与踩坑记录中**去本地化**提炼而成，不含任何特定机器的路径、账号、IP、
> 软件实例或个性化配置。它把"人类视角的经验"转写为"Agent 视角的执行约束"：
> 全部条款为祈使句或 If-Then 条件句，供 Agent 在 Windows 设备上无歧义地解析与执行。

## 使用方式（Agent 必读）

仓库根的 `../README.md` 只在**首次部署**或**判断是否与其他已装文档重复**时读（含抓取端点、校验方式、重合登记）；
**日常执行任务不要读它**，本表就是加载入口。

1. **每次会话开始时**加载 🔴 核心必读四件（00/01/02/03），它们承载跨任务的执行契约。
2. **按任务类型定向加载** 🟡 场景触发文件：先在下表中匹配"触发场景"，只加载命中的 1～3 个文件，
   不要一次性读入全部文档（上下文窗口是稀缺资源）。
3. **遇到故障需要归因时**再加载 🟢 扩展参考文件。
4. **任何文件都不得替代实时探测**：所有数值、路径、工具可用性、安全软件行为都必须
   在执行前动态获取（见 00 的前置探测指令）。本文档集只提供方法与判据，不提供环境事实。
5. **冲突裁决**：用户显式指令 > 项目 AGENTS.md 约定 > 本文档集 > Agent 默认习惯。
   本文档集内出现"本机/曾经/实测"字样时，一律理解为"需在当前环境复验的假设"。

## 优先级定义

- **🔴 核心必读**：无条件适用。加载成本极低（每个 < 2K token），收益是避免整轮任务报废。
- **🟡 场景触发**：只在命中触发场景时加载。每条规则都写成 If-Then，未命中条件的条目直接跳过。
- **🟢 扩展参考**：面向深度排障与取证，通常由 🟡 文件中的判据引导进入。
- **⚪ 非指导文档**：不约束 Agent 行为，供人类交付与协作使用；Agent 不得为"执行任务"而加载它们。
  本仓库的指导文档为 `00`–`12`（即本目录内的编号文件）；仓库根的 `README.md` 与本目录的 `_INDEX.md`
  属非指导文档（本目录即文档集本体，`00`–`12` 共 13 个编号文件 + 本索引）。

> **仓库结构提示**：本目录（`win-work-precautions/`）就是文档集本体；`README.md` 与 `LICENSE` 位于仓库根。
> 本目录内引用同目录文件直接写文件名；引用仓库根的 `README.md` **必须**写作 `../README.md`——
> 裸写 `README.md` 会被按本目录解析而落空，导致部署校验误判为"README 缺失"。

## 维护约定

- 新增经验先判断归属主题文件；跨主题的通用执行契约进 `03`，故障定性流程进 `10`。
- 禁止写入：绝对路径、用户名、内网 IP、特定软件版本行为、任何仅在一台机器上成立的事实。
  若某条款依赖特定软件存在，必须写成"先检测该软件是否存在，若存在则……"。
- 文件名保持小写字母/数字/下划线；新增文件必须同步登记进上表并标注优先级与触发场景。
- **跨层引用规则**：本目录内引用同目录文件直接写文件名；引用仓库根的 `README.md` 必须写作
  `../README.md`。裸写 `README.md` 会被按本目录解析而落空，导致部署方误判文件缺失。
- **每篇必须首节为「前置探测」**：位置在文件开头说明块之后、任何实质条款之前，形如
  `## 前置探测（<时机>）`。内容只列该主题**必须现场获取**的事实项（3–6 条），不得把结论写死。
  这是 Agent 能"先探测再动手"的唯一保证；新增文档必须带此节，否则不予登记。
- **主题不重叠**：一个动作只在**一篇**里写处置步骤。`11` 只出判据与取证方法，处置动作归
  `04`/`06`/`12`；同一句操作说明不得在两篇中各写一遍。新增条款前先 `grep` 全文确认无同义重复。
- **禁止自增计数**：任何"共 N 项/条/个文件"的写法都会在维护后失真。要口径就指向某张表，
  或写成可复算的表达式；正文不得出现与表脱钩的独立总数。
