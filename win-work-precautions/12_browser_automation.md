# 12 桌面与浏览器自动化（Desktop & Browser Automation）

> 优先级 🟡 场景触发。加载条件：要操作图形界面窗口、接管浏览器做网页交互、
> 或采集网页/界面内容。与 `11` 的区别：本文管"怎么做不闯祸"，`11` 管"坏了怎么归因"。

## 前置探测（动手前必做，全部只读）

1. **浏览器与实例面**：目标浏览器可执行文件路径、版本；是否已有同名进程在跑（进程名 + 可执行路径**双向**确认，同名不同路径的实例不算同一个）；用户主配置目录是否被占用。
2. **调试通道**：目标端口是否空闲、是否已有调试端点存活——探测前先确认端口归属，不要盲连别人的实例。
3. **显示与输入环境**：分辨率与缩放比、是否多显示器、是否远程会话（远程会话下截图与键鼠合成的行为不同）。
4. **输入可用性**：是否必须用操作系统级输入（决定是否触发"征得同意"分支）；系统辅助功能/自动化权限是否受限。
5. **被测应用形态**：主窗口与子进程窗口的归属关系（进程树 + 窗口枚举确认，不靠猜测）。
6. **登录态与抓取边界**：是否必须复用用户登录态、该站点的采集与登录红线（见 `08`）。

任何一项探测失败，记录为"未知"并用最小成本手段验证后再动手，不得用假设替代。
探测结论只作本次会话判据，禁止写进脚本常量或长期记忆。

## 通用红线

- **零键鼠劫持优先**：能在浏览器沙箱内用调试协议合成事件完成的，绝不用操作系统级
  坐标点击与键盘模拟。禁止用屏幕绝对坐标作为唯一定位手段。
- If 必须使用操作系统级输入（无调试接口的原生窗口），Then
  先声明"会短暂占用光标/焦点"并取得用户同意，且每次输入前重新置顶目标窗口、重新取坐标。
- **不移动全局光标、不抢键盘焦点**是默认目标；用户可能在同一台机器上并行操作。
- If 任务涉及对外可见的写操作（发帖、提交表单、修改线上数据），Then
  先复述目标对象与后果再执行；登录态下的写入会真实改变用户线上数据。
- 每次动作后**验证效果**（页面标题/URL/元素状态变化、控件值回读），
  无变化就如实报"未生效"，禁止用"应该已点击"糊过去。

## 浏览器自动化

- 定位策略：DOM 选择器与语义角色优先，坐标只在无选择器可用时兜底，
  且坐标必须来自**紧接其前的一次截图**（滚动、重排后坐标必偏）。
- 元素引用有生命周期：快照式引用（ref）在页面变化后失效，必须重新取状态，
  不要把旧引用当有效句柄继续操作。
- 输入控件处理顺序：等元素就绪（存在 + 可见 + 可用）→ 若被建议下拉/遮罩覆盖先按
  Escape 或点空白 → 可信点击取焦 → 全选清空 → 再输入 → 回读值校验。
  **回退重试前必先清空**，否则会出现内容叠加（重字/重复串）这类脏数据。
- 脚本式填值（直接赋值 + 派发事件）不会触发逐键监听逻辑（自动补全、实时校验），
  需要下拉建议时改用真实按键事件序列。
- 用户代理等上下文覆写常需在**导航之后**再套用一次才反射到页面；
  覆写参数只传需要的字段，传空值会让覆写静默失效并被异常吞掉。
- 全新独立配置目录没有用户历史与登录态，且可能触发人机验证（网络不稳时验证脚本都加载不出）：
  需要登录态就复用用户主配置目录（先彻底关净现有浏览器实例），
  仅做隔离测试时才用独立配置。给用户的桌面入口默认复用主配置以保留登录态（用户长期偏好）。
- If 站点强依赖 WebSocket 而当前代理不透传（表现为首页能开、会话超时），Then
  按 `08` 切透明隧道/整机模式，不要反复刷新或改站点配置。
- 收尾：只回收自己启动的实例（按专属数据目录精确匹配进程命令行），
  不误伤用户日常浏览器；退出前确认自己起的进程计数归零，避免留下持锁的僵尸进程
  （残留进程会让后续复制配置的操作因文件被锁而失败）。

## 原生窗口自动化

- 先枚举窗口与控件树（语义定位：自动化 ID > 控件名称 > 控件类型 > 类名，取最高分），
  无命中再降级到截图 + OCR。
- If 目标应用把内容托管在**独立子进程窗口**（内嵌浏览器/组件化渲染），Then
  必须枚举该子进程的大窗口来操作，主进程的窗口里可能只是侧栏；滚错/点错窗口等于白做。
- 输入序列纪律：置前 → 点击目标控件 → 短暂等待 → 输入 → 点击确认。
  **点击输入框后不要再调用置前类 API**，否则会抢走刚设置的输入焦点导致字符丢失。
- 界面元素位置与标签顺序会随会话/版本变化：每次点击前用当前截图校准，
  不要沿用上一步的坐标或索引。
- 高危动作（点击、输入、删除）未获授权时返回"需人工授权"并停在该步，不硬执行；
  提供全局急停与预演（dry-run）；操作留痕可审计。

## 采集类任务的合规与稳健性

- 遵守站点抓取边界（robots 与访问频率），限速、加间隔、命中验证码/风控立即暂停并回报。
- 只采集任务所需字段，个人敏感信息默认脱敏；不落盘明文凭证。
- If 站点要求登录才能访问目标内容，Then 使用用户本人的单账号登录态，
  不做账号池、不做指纹伪装、不破解验证码（红线见 `08`）。
- 解析结果先做结构断言（条目数、必需字段存在、时间戳可解析）再消费；
  用宽匹配判"完成"容易误收导航/模板链接（例：以 `'download' in href` 判定下载链接到位）。
- 若目标内容在公共存档服务上不存在，明确写"架构性不可得"并给出判据
  （多平台交叉一致为空），不要用近似内容冒充。

## 失败上报

- 每步失败给三行：做什么、实际现象（含错误码/页面证据）、下一步建议。
- 不谎报成功率，不把"部分完成"写成"已完成"；交付时如实标注未覆盖的场景。
