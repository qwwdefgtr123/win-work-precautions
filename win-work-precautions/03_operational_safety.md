# 03 执行契约与数据安全基线（Operational Safety）

> 优先级 🔴 核心必读。本文是不可协商的执行契约，适用于所有 Windows 任务。
> 其余文件是"怎么做对"，本文是"不许做错到哪一步"。

## 执行契约（无条件遵守）

1. **先核实再动手**：执行任何依赖环境状态的操作前，重新探测进程、文件、服务、网络的实际状态，
   不依赖同一会话中早先的扫描结果（用户可能已并行改动）。
2. **可逆优先**：先快照（还原点/注册表导出/配置备份/文件复制），后变更；
   变更一步、验证一步，不要连续多个不可逆动作后再统一检查。
3. **读回校验**：任何"成功"必须以效果为准——回读注册表值、`Test-Path`、比对哈希、
   看副作用文件、功能实测。**命令返回码与提示文案都不算数**（实测存在返回 0 但未生效、
   回执"已成功重启设备"但故障依旧的情况）。
4. **禁止静默失败**：If 脚本无输出且退出码为 0，Then 视同失败，必须定位原因（语法预检、
   产物文件是否存在、逐步骤落 log）。提权/后台脚本尤其要步步落 log，否则夭折点无从判断。
5. **不谎报**：If 未验证，Then 如实说明"未验证/无法点名"，禁止把猜测写成结论。
   工具失败要如实上报，不得用"应该没问题"填补。
6. **拿不准先问**：涉及用户数据、破坏性变更、不可逆对外动作时，宁可停下来确认，
   也不要把小概率风险当作零。
7. **超时 ≠ 失败**：批量操作工具超时后先检查是否实际已执行（看副作用），
   避免重复执行造成状态污染（例如重复删除、重复登记队列）。

## 数据安全底线

- 删除用户文件/目录：必须走系统回收机制（回收站/Trash 类可恢复操作），
  **禁止** `rm` / `del` / `rd /s /q` / `unlink` / `Remove-Item` / 语言运行时删除 API 直接永久删除。
- 唯一例外：为释放**系统盘**空间而清理缓存类数据时，可直接永久删除
  （回收站位于系统盘，进回收站等于不释放空间）。判定为"缓存"须满足：
  应用可自动重建、不含用户创作内容、不在用户文档目录内。
  该例外仅适用于自己创建或明确可重建的内容；受系统或其他账户保护的子项（如其他用户 SID 的回收站目录）
  不在授权范围内，不得强拆。
- AI 会话工作区/输出目录中的产物默认保留，除非用户明确要求清理。
- 修改用户文件前先备份原件（版本控制库内文件除外）；
  高风险批量变更（结构重组、格式转换）改为在别处生成副本，由用户决定是否替换。
- 冲突处理零删除纪律：迁移/整理遇到同名或双份文件时，按修改时间取最新归位，
  旧版改名 park 到暂存目录，**绝不覆盖、绝不删除**。

## 任务收尾

- 若临时修改过系统配置（代理、DNS、电源、服务启动类型、防火墙），任务结束后恢复原值并读回确认。
- 检查系统目录（如 `C:\Windows\System32`）是否残留提权脚本写出的临时文件，有则清理。
- If 用户未要求持久变更，Then 不留下自启项、计划任务、注册表 Run 项。
- 交付产物时给出可直接打开的位置与简短结论，不复述全过程。
