# 10 异常处理与回退（Error Handling & Fallback）

> 优先级 🟡 场景触发。加载条件：命令失败/挂起、结果与预期不符、怀疑被拦截、需要降级方案。

## 前置探测（判定失败之前）

1. **失败发生在哪一层**：命令没跑起来 / 跑了但输出不可信 / 跑了且确实失败。三类处置完全不同，
   混在一起就会得出"重试几次"这种无效结论。
2. **产物是否真的没有**：先确认输出文件是否存在、内容是否完整——回显不可信是常态，不要先信回显。
3. **返回码与副作用的组合**：返回 0 但无产物 = 失败；返回非 0 但有完整产物 = 需查明原因再决定。
4. **是否被拦截而非出错**：安全软件/策略的拦截常表现为静默无输出或"成功但未生效"，
   判据是副作用是否存在，不是提示文案。
5. **是否只是慢**：区分"挂起"与"耗时超预期"，看进程是否还在推进（CPU/IO/日志是否有增量）。
6. **降级的硬证据**：声明"这条路技术上不成立"之前，必须已有可复现的尝试记录与失败形态，
   否则只能报"未完成"，不能报"不可行"。

探测阶段不改环境；确需临时变更时先记录原值，收尾恢复并回读确认。

## 失败定性五步（按序，别跳）

1. **输出层失真**：命令可能已经成功，只是回显不可信。先确认产物文件是否存在、内容是否完整
   （见 `01`/`02`）。多行输出被终端吞成首行、`Out-File` 未落盘、UTF-16 误读都会制造假失败。
2. **编码/路径被破坏**：静默返空、ParserError、"找不到文件"常源于脚本编码或路径转义
   （无 BOM 的脚本被按 ANSI 读、非 raw 串吃转义、LF 写的批处理）。做最小可复现样本验证。
3. **shell 层改写**：变量被提前展开、`/` 前缀参数被转成路径、`://` 被破坏（见 `01`）。
   改用数组式参数或落地文件执行来验证这一层。
4. **权限/策略拦截**：对照实验定性——"新建可以、改已有不行" = 策略层；
   "改名可以、删除不行" = 内核 IO 拦截；"提权后仍不行" = 需要更早执行点（见 `06`）。
5. **逻辑或环境假设错误**：以上都排除后，才回头怀疑自己的判断依据（是否用了陈旧状态、
   是否把名称当内容、是否把返回码当成功）。

## 超时与挂起

- If 长任务超时，Then **先捞部分产物**：读已落盘的中间输出、日志尾、临时目录，
  再决定是否重跑（实测有"整体超时但关键结果已写完"的情况）。
- If 进程 CPU=0 却长期不退出，Then 怀疑交互式提示在等待输入（部分系统维护命令结尾会读 Y/N），
  重定向时补 `<nul` 或改为轮询确认后再结束。
- If 输出文件被另一进程占用，Then 换文件名而不是等待；残留的旧 shell 常占着日志。
- If 提权/后台脚本不返回，Then 不要用 `-Wait` 阻塞主流程；改后台启动 + 轮询完成标记文件 + 读回。
- 提权脚本的产物是异步生成的：读取前留轮询窗口；**产物文件完全不出现**通常意味着
  脚本在解析阶段就失败了（做语法预检），而非逻辑失败。
- 长任务必须设**轮次/时长上限**并落进度，否则无法区分"卡死"与"就是慢"。

## 被拦截时的降级阶梯

1. 换更轻的手段达成同一目标（只读采集替代写操作；新增键替代改存量键）。
2. 换执行点（开机队列、离线环境、安全模式）——仅在需要且用户同意时。
3. 换通道（下载走可达镜像、代理走透明隧道、解析走外部服务）。
4. **交付脚本给用户手工执行**：当自动化路径被安全策略明确封堵时，
   把带自检与备份能力的脚本 + 清晰说明交给用户，是最快也最稳的降级。
5. 停止并如实说明：If 继续推进需要削弱系统防护、绕过风控、或牺牲用户数据完整性，Then 停手。

- **降级需要硬证据**：用户会要求先试更底层的手段。要提出降级，须给出"技术上不成立"的证据
  （同一操作在多通道/多执行点的一致失败矩阵），而不是"麻烦/风险大"。
- 拒绝把破坏性操作当降级手段（例如为通过校验而删数据、为省事改用户配置基线）。

## 结论纠错

- If 发现自己此前结论错误，Then 显式回滚改判并在文档/报告中留下判据（错误结论比未知更有害）。
- 常见的"错判成对"模式，动手前先自问：
  - "文件不存在" ≠ "文件被删"（该文件在本版本系统中可能本就不存在；先查组件清单与实际引用）。
  - "清单类校验说无损坏" ≠ "文件都在"；反之"校验说无损坏"在多数情况下是对的，
    坚持"它漏检了"需要日志级证据。
  - 错误码不是根因：统一的"拒绝访问"类错误在文件缺失时同样会出现，不能据此断定权限问题。
  - 服务/进程"回执已成功" ≠ 故障消失；判据永远是故障征候本身。
  - 名称、卷标、目录命名风格不是内容判据。
- If 结论会影响不可逆动作（删除、卸载、覆盖），Then 必须达到"三源交叉一致"才动手
  （见 `11` 的取证方法）。

## 恢复与安全网

- 系统级变更前创建还原点；同一变更序列前后各留一次可回退点。
  若还原机制有频率限制，可临时放开后立即改回默认值。
- 备份优先级：注册表导出 > 配置文件复制 > 目录搬迁（可回滚）> 直接删除（不可回滚）。
  用"搬到暂存目录"替代"删除"能同时释放系统盘并保留后手。
- 卷影副本既是恢复手段也是取证手段，但保留窗口很短，重要排查要趁早。
- 若变更引入悬空引用（配置指向已删目标），系统组件修复类操作会以"路径不可达"形式失败：
  修法是先删除悬空链接、重建真实空目录，再让系统自行回填。
