# 07 包管理与依赖配置（Packages & Dependencies）

> 优先级 🟡 场景触发。加载条件：要安装/卸载软件或工具、下载依赖、补齐运行环境、
> 处理"命令找不到"或"装了但叫不到"。

## 工具使用前检查（禁止预设）

- **本文档集不预设任何第三方工具存在**。要使用任何外部工具，先执行存在性检查：
  `Get-Command <name> -ErrorAction SilentlyContinue` 或 `where.exe <name>`，并记录解析到的路径与版本。
  检查失败时按"探测 → 取源 → 校验 → 登记"流程补装，或改用已确认可用的替代手段。
- 若目标目录下已有工具库/清单文件，先读清单再找工具，不要重复下载或重复造轮子。
- 解释器调用注意别名缺失：某些编译器发行版只提供三元组全名而不提供短别名，
  硬编码短名的构建脚本会静默失败 → 用 `Get-Command` 解析实际可执行名。
- **不要硬编码解释器绝对路径**到脚本、注册表或计划任务里；
  用 `Get-Command` 动态解析。需要写入持久配置时，校验目标文件存在且优先用户可控的安装位置。
- 无窗口场景（右键菜单、计划任务、协议处理器）调用脚本时，选用 GUI 子系统的解释器
  （如 `pythonw` + `.pyw`）避免控制台黑窗闪现；`.bat` 只留给用户主动双击的场景。
  无窗口的代价是看不到 stdout → 必须自行落盘错误日志（带时间戳、追加模式）。

## 安装通道决策

- 包管理器可用性要现场判定。常见失效模式：包管理器下载器不走系统代理
  （直连被墙源导致超时）；便携版安装时在受限令牌下创建符号链接失败。
- If 包管理器失败，Then 改走官方发布物的直接下载 + 手工安装（等价达成"系统级安装并进 PATH"的目标），
  不死守单一通道；If 需要机器级 PATH 与组件注册，Then 用安装包（MSI 类）静默安装并传"加入 PATH"参数，
  安装属提权动作要按 `06` 的通道执行并放到后台等待用户确认。
- 便携版落地后若不在 PATH：在自己的工具目录放 `.cmd` 垫片收口，不要污染全局 PATH；
  垫片文件内容必须纯 ASCII（见 `02`）。
- 归档解包：系统自带归档工具可能打不开部分压缩包（首字节是 zip 魔数却报错），
  改用脚本语言的归档库解压；自解压包注意参数格式（输出目录参数与路径之间不能有空格）。
- 下载大文件时先按 `08` 判定可达通道；若通道存在按连接限速，用分块并发（Range 切片 + 多连接 +
  按序合并 + 每片字节数校验 + 缺片重试）提速，而不是反复重下整包。

## 供应链与完整性校验

- **下载后必校验类型**：`file`/魔数检查（tar.gz = `1f 8b`，zip = `50 4b`，PE = `MZ`）
  并与发布方标注的字节数对齐。HTTP 200 与 `.exe` 后缀都不代表拿到真文件——
  镜像/代理站常返回 HTML 错误页；不加跟随重定向只会拿到几百字节的跳转页。
- 校验数字签名链（发布者 + 状态）作为可信度证据；发布方未提供校验值时，
  把"证据强度"如实写进结论（尺寸一致属弱证据），需要强证明时改走带哈希钉定的通道。
  未签名不等于恶意（部分工具官方即不签名），但必须降低信任等级并说明。
- 需要用户许可协议的工具（部分系统级诊断套件）常首次运行弹许可框，会卡住自动化：
  先在用户配置单元预置"已同意"标记，再调用。
- 若目标程序是"单文件可执行 + 同目录依赖库"结构，复制单文件会静默无输出 → 必须保留官方目录结构，
  只在 PATH 目录放调用垫片。
- 不安装与任务无关的组件；不为了"顺手"升级用户已有工具链。重型框架（需 GPU、需付费密钥）
  只归档与说明，不实际部署，避免污染环境。

## 卸载与残留清理（用户的彻底标准）

- 卸载一个应用必须连根清：应用目录 + 快捷方式（桌面与开始菜单，用户与公共两处）
  + 注册表卸载键及子键（三个视图：HKLM、HKLM 的 32 位视图、HKCU）+ 支持库与用户数据目录
  （漫游/本地/公共应用数据、以及用户自定义安装根目录下的该应用目录）。
- 注册表卸载表要三视图交叉核对，只查一处会漏。
- 商店应用（打包应用）操作要点：
  - 卸载前先按版本排序保留最新版，**按包全名精确指定**，
    禁止对整包名跑"全用户"循环（会连带卸载同包名的在用新版本）。
  - 已"不可见"的孤儿包：卸载命令报错也别放弃，执行一轮后复查目录与预置清单即可收口。
  - 变更应用默认安装卷必须走系统设置界面；手改注册表卷映射键无效。
- **版本目录 ≠ 安装残留**：删旧版本目录前，必须确认无进程持有其内部文件的陈旧句柄
  （自动更新后主程序可能仍引用旧版资源文件），且要先关闭该应用全部窗口。
- 安装器缓存目录（供驱动/SDK 重建用）不要随手删除；打包缓存可能与开发工具链绑定。

## 配置漂移治理

- If 你或第三方工具改过系统配置（DNS、路由跃点、TCP 参数、服务启动类型、更新开关），Then
  记录"预期基线"并周期性只读复核；发现漂移要能区分"被回滚"与"从未生效"。
- 服务启动类型：图形化设置命令对打包服务的虚拟账户可能无效，改用注册表 `Start` 值；
  改后当前会话仍在运行属正常（依赖拉住），下次重启才生效——别误判为失败。
- 定时巡检类任务应设计为**只报不删**，把处置权交回用户或下一轮决策。
