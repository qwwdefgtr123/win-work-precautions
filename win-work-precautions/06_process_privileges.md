# 06 进程、权限与安全软件共存（Process & Privileges）

> 优先级 🟡 场景触发。加载条件：命令报"拒绝访问"、需要管理员/系统级权限、
> 要启停服务或杀进程、新编译程序异常消失。

## 前置探测（提权 / 进程操作之前）

1. **令牌形态**：当前进程是否提权、是否属于管理员组但被 UAC 过滤（`IsInRole` 为 False 是正常现象，
   此时必须走显式提权通道，而不是重试同一命令）。
2. **目标对象的真实身份**：按**端口/句柄/服务**反查属主 PID 与可执行路径，不要只按进程名认人
   （同名进程可能是完全不同的程序，也可能是用户正在用的）。
3. **是否有监管者**：目标进程/服务是否被宿主进程、服务管理器或安全软件托管——直接杀掉会被立刻拉起，
   要先确认监管链。
4. **提权通道可用性**：本机存在哪些提权方式、是否可用、是否需要交互确认；通道自身的返回值语义要先查清。
5. **安全软件的当前状态**：是否在拦截、拦截形态是什么（静默拦截 vs 报错），决定后续策略层级。
6. **收尾责任**：本次启动的进程/服务由谁回收，怎么验证已归零。

探测阶段不做任何终止、提权或配置变更动作。

## 令牌与提权通道

- 先按 `00` 探测令牌形态。账户在管理员组但 `IsInRole(Administrator)=False` 是正常现象
  （UAC 过滤令牌），此时必须走显式提权通道，而不是反复重试同一命令。
- **通道优先级**：
  1. **原生 API 的 `runas` 动词**（如 Python `ctypes.windll.shell32.ShellExecuteW(None,'runas',...)`）
     —— 对含非 ASCII 字符的路径/参数最稳（UTF-16 传参，不经代码页转换）。
     **返回值 > 32 才算成功**，≤32 是失败码。
  2. `Start-Process -Verb RunAs` —— 在部分环境时好时坏（同一写法有时静默退出码 1）。
     用它时**不要加 `-WindowStyle Hidden`**（有导致提权失败的环境），
     也不要同时给 `-RedirectStandardOutput` + 隐藏窗口（参数集冲突，子进程根本不启动）。
  3. 更高权限（组件所有权级别，如改受保护系统目录/键）：先经 1/2 拿到高完整性令牌，
     再从该会话内启动提权工具。**不要一上来就走最高权限通道**，能直接提权解决的不必绕。
- If 静默无输出，Then 先用最小脚本单独验证提权是否真生效（跑一条 `whoami /groups` 落文件），
  再排查业务逻辑——多数"脚本坏了"其实是外层参数拼装坏了。
- If 提权脚本内使用相对路径或依赖工作目录，Then 改正为绝对路径：
  提权后默认工作目录常是系统目录（`C:\Windows\System32`），会把产物写到意外位置并留残留；
  父进程指定 `WorkingDirectory` 只对启动的 exe 生效，脚本内部的写入不受影响。
- 提权脚本要**拆小**：只放确实需要管理员权限的采集项（SMART、卷影、BitLocker、TPM、恢复环境、
  卸载表等），其余留在普通令牌跑。混合大脚本极易超时且零产出。
  单脚本含多种长耗时系统操作时按耗时上限拆分（健康扫描、映像分析类各自可占分钟级）。
- If 提权后仍"拒绝访问"，Then 依次判断：所有者与 ACL → 是否被安全软件 IO 层拦截
  （改名可过、删除被拒 = 拦截删除操作，不是权限）→ 是否需要更早的执行点（开机队列、安全模式）。
  **别默认往"组策略/权限不足"方向查。**

## 进程操作

- **不要按进程名批量杀**：会误伤用户常驻进程。自启的服务/进程要按**端口反查 PID**
  （连接表里找监听端口的属主进程）再精确终止。
- 停"主动防御"类服务：同步等待 `stop` 可能挂死整个提权进程。
  → 异步发停止信号 + 轮询状态判据（服务状态、驱动/过滤器是否摘除），设超时上限。
  此类服务常秒级自愈，判据不满足就放弃该路径（见下"共存策略"）。
- 判断进程为何秒退：同步跑并看返回码——返回 0 多为自检环境后主动退出；
  参数错误码（如 `E_INVALIDARG`）说明它必须被带参调用。别把它当崩溃反复重启。
- 进程宿主关系（谁拉起谁、谁锁哪个文件）必须用**句柄 + 配置 + 自身数据目录**三证核验，
  不要轻信进程名、描述或单一来源说法。

## 与安全软件共存（通用策略分层）

现代国产/第三方安全软件会在 IO 层与进程层做自我保护。按下述分层选择手段，
**不要靠加权限硬闯**：

1. **预防层**：若环境策略会拦截新生成的可执行文件（表现为新编译/新下载的程序异常消失，
   而源码无恙），Then 先检测该现象是否存在（新建探针程序，隔一段时间复查）。
   确认后按顺序尝试：请用户把工具链与工作目录加入白名单 → 静态链接减少外部依赖
   （同时规避运行库解析类启动错误）→ 把编译与首次运行放在同一条命令链内完成（缩短被删窗口）。
   已消失的程序用源码重建即可，不要反复重下。
2. **绕过层（推荐）**：比防护更早的执行点——开机删除队列、安全模式、离线环境。
3. **时序层**：短暂窗口内完成删除，之后靠只读巡检复核，不追求永久封死。
4. **对抗层（默认不做）**：摘除内核过滤器、写注册过滤驱动、降级启动链签名校验、
   绕过驱动签名强制。代价（系统不稳定、启动链降级、可能蓝屏）远大于收益，
   属须用户显式决策的高风险区。
- **文件凭空消失的诊断顺序**：先怀疑安全软件实时隔离（尤其脚本内容含可疑特征串时，
  扫描通道可能命中），再怀疑工具故障。验证防护是否真的在工作要**双载体交叉**
  （脚本内容通道与可执行文件通道表现不同）且观察窗足够长，短窗内无动作不足以定"失明"。
- 若必须压制推广/自启行为，按有效性排序：防火墙按程序路径的**出站阻断**（存于受保护存储，比 hosts 耐篡改）
  > 更早执行点 > hosts 屏蔽（会被精确编辑，只删自己加的行）> ACL 占位锁 / 注册表 Deny 锁（辅助层）。
  **占位锁教训**：给"将来还要删"的东西加"拒绝删除"的锁是自相矛盾——Deny 优先于 Allow，
  连系统与开机清理都会被挡住，净收益为负。占位锁最多拒"写入/建目录"，不带删除位，且只加在空目录上。
  任何锁都必须**回读验证**（返回码 0 不代表 ACE 生效），撤锁要反复跑到回读无残留并检查子项继承。
- 若软件会把删进回收站的组件"原样还原"：删除后立即清空回收站；
  其离线缓存（本地安装包/P2P 缓存）会支持不联网回补，故"断补给 → 再删"顺序不可颠倒。

## ACL 修改

- 收紧权限用显式禁继承的工具链（先"禁用继承并转为显式"，再移除宽泛授权，再按需授予只读），
  直接用 ACL 对象移除继承来的规则**会被重新继承回来**。
- 判"锁是否生效"要**功能实测**（真去写一个值看是否被拒），解析文本或看返回值都会误报。
- 夺所有权前注意：管理员令牌里"取得所有权"特权默认禁用，需先启用特权再改所有者。
